# 楼栋财务问数Agent · OBS-V31 / R38 / T09-T10 V8

本地网页问数应用，绑定已核验的OBS-V31 / R38 / T09-T10 V8。采用自编顺序状态机、FastAPI、参数化只读SQL和SSE流式输出；新版运行不依赖LangChain/LangGraph。旧实现保留作历史参考。

## 启动

在本目录运行`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\启动.ps1`，打开http://127.0.0.1:8765。保持服务运行；更新后刷新页面并新建查询。

首次启动自动创建虚拟环境并安装`requirements.lock.txt`固定版本。Python 3.11及更新版本可用。

## 查询入口

- 项目：直接输入“石厦公社2026年1月至9月每月实收、应付、实付和差额”。
- 楼栋：输入“石厦公社西村167号2026年1月至4月我方应收费用”。
- 合同：在查询方式选择合同，填写合同ID或完整合同名，也可以直接把合同ID写进问题。
- 实付单据：把完整单据号写进问题，查看单笔金额、同月成功实付及应付差额。
- 查看执行合同：输入“石厦公社2026年1月有哪些执行合同”。

唯一完全匹配或唯一超过90%的对象直接采用，结果明确列出对象；需要候选确认时仅显示超过90%的候选，否则显示前5个。名称分数不是概率，多个高匹配对象仍需选择，不能猜楼栋或合同。

未指定月份查全部已存日期；单据查询未指定账期时采用单据的来源月份。明确按实际付款日期、具体日或相对日期的分析尚不支持，不会偷换日期口径。

## 页面与SQL

默认SSE长连接输出任务解析、范围匹配、取数规则、SQL编排片段、参数和执行状态；完成后展示每月明细、合计、执行合同、来源及相关楼栋。

“任务解析与SQL编写过程”默认展开；“实际执行SQL及全部绑定参数”可查看最终执行语句。SQL由服务端按审核规则编排，不将未经验证的模型SQL或私有推理作为业务结论。查询中可点击“停止接收”，没有自动重试。

## 当前金额口径

新实收＝当月租赁＋赔偿＋上一费用账期水电；新应付＝当月租赁＋赔偿－预留＋已确认调整。采用R38整数分表，缺失不补0。

每月实付采用T09分摊实付登记；T10有效核销及单据端未对应余额分别列示。V6反算账单收益不作为新实付，已撤回核销不自动恢复。共享合同余额不全归单栋，账单月与单据登记月区分。差额不等于核销后欠款。

详见[口径、来源及验收](docs/10_R38实收应付与实付核销查询.md)。

## 提示词、规则与Key

提示词：`knowledge/r36_prompts.json`，仅约束复杂问题的实体提取。规则：`knowledge/finance_v31_rules.json`，包括版本、实收口径、应付公式、匹配与金额归属约束。

向量数据库不是必需条件。当前沿用本地SQLite字符TF-IDF规则检索，强制加载关键业务规则，不需要额外Embedding Key或远程向量服务。明确输入优先本地解析；仅难以提取对象时调用DeepSeek，不为固定SQL额外发起模型请求。

Key仍只保存到`secrets/deepseek_key.txt`，`config.local.json`只写路径。不要在聊天、网页问题框、代码或Git提交中写Key。助手每次真实API测试仍需单独确认；无自动重试，开发测试禁止读取真实Key。用户自行提交业务查询与助手测试区分。

本次只更新Agent的数据库/验收文件绑定，保留用户Key路径、接口地址和模型选择，不修改业务库、Excel或正式入口，不上传GitHub。
