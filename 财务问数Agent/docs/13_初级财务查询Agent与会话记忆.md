# 初级财务查询Agent与会话记忆（2026-10-28）

## 一句话结论

第一版采用显式工作记忆和结构化会话状态，辅以最近6轮对话；不建完整长期记忆。上下文窗口只是本轮输入，不是唯一事实源。业务金额每次从已验收SQLite重新读取。

## 运行路线

自由输入 → 理解查询目标、月份与输出要求 → 澄清缺失指标或冲突 → 匹配项目/楼栋/合同/单据 → 必要时复述确认 → 按需参数化只读SQL → 精简结果与可展开依据。

问题完整、对象唯一时直接查询，避免重复确认。经过追问或模型辅助推断的需求先复述，再由用户确认；确认后若继续修正，撤销旧确认并复述新版本。未指定月份查全部已存日期；短追问继承已确认期间与年份。独立完整新对象问题重新建立槽位，避免沿用无关月份。超过90%的匹配沿用原规则，名称分数不是概率。

界面支持自由文字、候选按钮和文字选项编号。按钮只填入可编辑示例，不强迫使用按钮。默认回答目标金额，不展开全部财务字段。每月、仅合计、明细等由output_spec决定；资料完整性给短标签，原因和覆盖范围可展开。SQL、来源、版本仍可追溯。

## 记忆裁剪与存储

|类型|存什么|位置|生命周期|主要失效模式与处理|
|---|---|---|---|---|
|工作记忆|本轮结构化需求、最近6轮、必要工具引用|Python本轮对象|一轮结束释放；工具引用仅保留少量|上下文太长则只取最近消息和2400字符结构化摘要|
|会话状态|slots、constraints、assumptions、pending_questions、confirmed_items、output_spec、version、status、时间戳|runtime/session_memory.sqlite 的sessions|活跃有效期24小时；旧状态最多保留7天，保存时惰性清理|版本冲突拒绝覆盖；过期明确要求新对话；重启仍可恢复|
|幂等回执|请求ID、输入摘要、处理中/完成/中断状态、短期结果回执|同库turns|最多24小时，保存时清理|相同ID不同内容拒绝；重复完成请求回放；中断请求不自动重试|
|业务事实|合同、费用、实付、核销及QA标签|已验收业务SQLite，只读|按正式数据版本管理|指纹变化后旧需求确认失效，旧金额回执不可跨版本回放|
|可选长期记忆|用户明确确认的稳定偏好、输出模板、常见需求模式|本版不启用；未来独立用户偏好表|届时显式确认、可查看撤回、带有效期|不得沉淀模型猜测、密钥、财务余额或全量聊天|

业务规则的本地TF-IDF检索属于知识检索，与会话记忆分开。记忆库不写入业务库。

## 五阶段生命周期

1. **抽取**：本地优先抽取对象、指标、月份、输出方式及排除项；难以解析时最多调用一次DeepSeek辅助结构化解析。模型输出不能指定SQL或直接确认自己推断的需求。用户明确输入、修正和系统默认值分别记录。
2. **整合治理**：补充只更新对应槽位；明确修正替换旧值，矛盾不拼成一个假范围。待确认事项单列，复述显示当前完整草稿；旧选择和旧state_version拒绝。不能识别的金额筛选或复杂统计明确阻断，不能默默忽略。
3. **存储**：结构化状态为准，每次有效响应递增版本；最近6轮及摘要辅助理解。历史助手金额不写入供模型复用的消息，替换为“已查询，金额需重新读取”。结果仅在24小时幂等回执中短期缓存，不能作为长期事实。
4. **检索**：读取本用户本会话状态，注入槽位、约束、输出规格、假设、待确认项、相关摘要和最近至多6条消息；不注入全量历史、不注入工具查得的财务明细。查询结果只在本地受控汇总和展示。
5. **遗忘/压缩**：超出6轮滚动压缩；取消将当前需求归档，继续输入建立新草稿。24小时未活动会话不可继续使用，超过7天在保存时删除。当前没有长期偏好沉淀或后台扫描任务。

## SessionState Schema及示例

正式结构见knowledge/session_state.schema.json。核心字段示例：

```json
{
  "session_id":"32位随机会话ID",
  "user_id":"服务端从本地HttpOnly随机cookie派生的标识",
  "slots":{
    "intent":"finance",
    "fields":{"scope_type":"building","project":"泊寓-南山新南公社","building":"14栋","entity":""},
    "metrics":["payable"],"start":"202603","end":"202603"
  },
  "constraints":{"excluded_metrics":["receipts","paid"]},
  "assumptions":["未注明年份的月份按当前需求年份2026年理解"],
  "pending_questions":[],
  "confirmed_items":{"metrics":{"confirmed":true,"source":"explicit_request","value":["payable"],"version":3}},
  "output_spec":{"mode":"total","details":false,"breakdown":false},
  "version":3,"created_at":1793000000,"last_updated":1793000100,
  "status":"answered","database_sha256":"本次已验收业务库指纹",
  "recent_messages":[],"summary":"受限长度的需求摘要","tool_refs":[]
}
```

status为draft → awaiting_fields → awaiting_confirmation → ready → answered；取消为archived。明确完整输入可直接从draft到ready。JSON Schema描述存储契约，实际入口还通过Pydantic、本地指标白名单、实体匹配、月份解析和SQL只读校验；不以模型JSON作为授权。

## 每轮处理伪代码

```text
服务端从HttpOnly cookie确定user_id；不信任请求JSON里的user_id
验证正式库绑定和指纹
读取(user_id, session_id)状态；过期则提示新对话
以request_id认领本轮；重复完成请求回放，同ID不同内容拒绝
如果有并发处理中请求或state_version过旧：拒绝，不执行模型/SQL
抽取本轮补充、修正、排除项和输出方式，合并草稿
若数据库版本变化：取消旧确认，重新核对
若指标或对象缺失：提出一个待确认问题（可选项或自由文字）
若补充/推断后需确认：复述全部当前需求，等待确认，不执行SQL
否则标记明确需求已确认，编排只需要的SQL并只读执行
按目标指标组织回答；未知与归属限制明确提示
滚动摘要，保存状态与幂等回执，CAS递增版本
返回需求版本、结果、来源、SQL和耗时
```

异步SSE负责接收和输出；同会话只允许一个处理中请求，数据库事务串行认领和提交，不在数据库事务中等待模型。CAS防止覆盖，120秒遗留running请求转中断后允许新请求；中断不自动重试。不同会话可并发。

## 工程选型与文件

- 原生HTML/JS、FastAPI、SSE保留，自编顺序状态机保留。
- agent/conversation.py：需求抽取、继承、修正、澄清、确认和受控模型上下文。
- agent/memory.py：SQLite持久状态、幂等回执、版本防覆盖、TTL和压缩。
- agent/query_plan.py：按目标裁剪已审核SQL模板及月度字段。
- agent/query_service.py：只读执行、目标汇总、简短回答、资料状态和依据。
- agent/engine.py：公共chat转入新协调器；旧逻辑仅兼容原尾期/计划等入口。
- knowledge/r36_prompts.json的conversation：结构化需求解析提示词，不生成SQL。
- app.py：隔离cookie、请求ID和版本、恢复状态接口。
- web/v2.js：sessionStorage保存会话ID和版本；刷新后从服务端恢复需求，不恢复旧金额；选项与文字输入并行。

本地单服务使用SQLite足够，不增加Redis、LangGraph或新的向量服务。以后多实例或高并发再评估Redis/服务端数据库；若迁LangGraph，可映射checkpointer管理会话短期状态、Store管理经确认的可选长期偏好。

身份隔离只针对本地匿名浏览器：user_id由服务端随机cookie派生，强制与session_id联合查询，接口不接受客户端覆盖。没有实现网站级账号登录；未来外网部署必须接入认证并使用真实服务端用户ID、HTTPS和Secure cookie，不能把当前匿名标识当作正式鉴权。

## 验收和可观测

验收用例覆盖明确输入、逐步澄清、文字/编号/按钮补充、确认后输出、修正撤销、上下文继承、排除项、独立新问题、NULL与空结果、共享合同、单据与整月区分、会话隔离、重启恢复、过期、并发认领、CAS、幂等、模型不能触发未请求工作流、SSE和原功能兼容。

|指标|采集与验收方式|第一版标准|
|---|---|---|
|需求确认完整率|标注用例检查对象、指标、期间、输出要求与确认状态|验收用例100%一致；缺项不执行|
|重复提问率|逐轮标注已给字段是否再被无故询问|验收用例0；生产候选需人工复核|
|槽位遗漏率|标注用例比较每轮合并后的需求与最终执行参数|验收用例0|
|冲突率|旧版本、并发、旧选项、同ID异内容注入|均拒绝，不覆盖、不执行第二条|
|token消耗|diagnostics记录model_calls、context_chars；真实模型响应usage仅在实际调用时记录|不捏造token数；模拟测试无真实API费用|
|p95延迟|统计diagnostics.elapsed_ms，另用HTTP/SSE完整耗时观察网络端到端|本地暖查询以2秒为观察目标；模型调用延迟单列|
|输出一致性|与独立SQL金标准比较金额、口径、NULL及只输出所需指标|测试金额到分一致；不添加无关指标|

诊断耗时截止生成待持久化响应，不含最终SQLite提交与网络传输。scripts/memory_metrics.py输出本地回执聚合诊断，不输出聊天、金额或密钥；需求语义正确率仍需标注测试，不从“响应成功”伪推。

## 不需要做

不建全量情景库、复杂知识图谱或聊天向量库；不每轮注入全量历史；不保存所有历史财务结果作记忆；不自动学习偏好；不引入多Agent或完整长期记忆；不开放大模型任意生成SQL；不改变财务库、金额、核销及正式入口。

本版支持对象、指标、连续月份、按月/合计和已有明细。不承诺任意统计SQL，金额阈值筛选、排名、同比等先明确能力边界。尾期生成与支付计划功能保留原工作流及确认约定。
