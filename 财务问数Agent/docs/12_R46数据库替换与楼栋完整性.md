## 数据库替换流程

1. 读取当前版本、当前正式Excel版本、当前结构版本、当前测试状态登记版本及正式验收；确认版本、数据库路径、SHA256、规则、T09/T10修订和QA登记一致。
2. 只读检查SQLite完整性、外键、财务资金守恒、QA唯一键、合同对应、工作簿指纹及严格财务清单入口。新业务数据库由财务版本流程产生，Agent不覆盖业务库或自动生成核销。
3. 在独立暂存目录适配并测试代码。备份现有Agent代码、绑定及本地配置；只将config.local.json中的database_file/validation_file同步为已验收版本，其他模型、接口及Key路径字段保留。knowledge/database_binding.json固定记录路径、版本、指纹及qa_rule_version，不移除版本保护。
4. 安装已验收代码，重启127.0.0.1:8765；重新读取/api/status核对实际加载路径、指纹及版本。用户刷新网页并新建查询，旧聊天结果不会自动变更。
5. 保留旧SQLite、旧代码备份和验收记录。回退应恢复成套代码与配置；若正式入口已前进，旧绑定会被拦截，不自行倒退正式入口。

每次真实财务数据库更新后的QA重检与严格清单生成由正式财务版本维护流程负责。本次只让Agent读取已发布QA登记，不在已验收正式库运行refresh_registry.py，也不改正式版本号或原始标签。
